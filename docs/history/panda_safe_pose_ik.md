# Panda 안전 자세 IK와 궤적 제어기

> 기존 설계·구현·실험 기록입니다. 본문의 현재·기본값은 작성 당시 기준이며, 현재 동작은 [구현 지도](../current/README.md)를 참고하세요.

## 처리 흐름

$$
q_0 \rightarrow \text{안전 자세 IK 탐색}
\rightarrow q^*_{safe} \rightarrow \text{CLF-CBF 궤적}
$$

목표 방향은 YAML에 정규화하지 않은 베이스·월드 좌표계 벡터 두 개로 지정한다.
`orientation.approach`는 `gripper_tip`의 로컬 +z축이 향할 방향이고,
`orientation.up`은 로컬 +y축이 향할 방향이다. up 벡터는 approach에
수직인 평면으로 투영하므로 두 벡터는 평행하면 안 된다. 이들로 원하는 로컬
+x, +y, +z축을 열로 갖는 오른손 회전행렬을 만들고, 내부적으로 스칼라 성분이
먼저 오는 쿼터니언 `[w, x, y, z]`로 변환한다. 위치, 방향, 변환된 캡슐 끝점,
장애물, Jacobian은 베이스·월드 좌표계로 표현한다.

## 안전 자세 IK

방향 오차는 `clarification.md`에 명시한 상대 쿼터니언의 벡터 성분이다.

$$
e_O = \eta_e\varepsilon_d-\eta_d\varepsilon_e
-\varepsilon_d\times\varepsilon_e.
$$

주 작업의 역행렬에는 감쇠를 적용하고, 영공간 투영에는 Moore–Penrose
의사역행렬을 사용한다.

$$
\dot q = J^\#_\lambda k_p
\begin{bmatrix}p_d-p\\2e_O\end{bmatrix}
+\left(I-J^+J\right)k_s\nabla_q\Phi(q).
$$

모든 장애물 장벽과 활성 자기 충돌 장벽을 다음과 같이 결합한다.

$$
\Phi(q)=-\tau\log\sum_i\exp\left(-h_i(q)/\tau\right).
$$

이 탐색에는 의도적으로 속도 제한과 완화 불가능한 CBF 제약을 두지 않는다.
각 초기 시드에 `safe_ik.iteration_number`로 최대 반복 횟수를 부여한다.
기본값 1000은 기존 `ceil(10.0 / 0.01)`과 같으며, 실제 10초 제한이 아니다.
양의 정수만 허용한다. 관절 업데이트는 기존대로 내부 수치 간격 0.01을 곱해
수행하므로, 반복 한도를 바꾸어도 한 번의 업데이트 크기는 바뀌지 않는다.
`trajectory.integration_period`는 실제 궤적 제어 주기로 별개이며 변경하지 않는다.
위치·방향 오차가 모두 허용 범위 이내이고 안전 여유를 반영한 모든 장벽이
$h_i\ge0$일 때만 후보로 인정한다. 이 조건들은
`ceil(safe_ik.convergence_hold_duration / 0.01)`회 연속해서 유지되어야 한다.
도중에 하나라도 깨지면 연속 횟수를 다시 센다. 기존 설정 3.0은 300회에
해당하는 수치적 유지 구간이지 실제 3초 대기가 아니다. 반복 한도가 이보다
작으면 후보를 확정할 수 없으며, 유지 조건을 자동으로 줄이지 않는다.
완료되는 것은 해당 시드의 탐색뿐이며, 설정된 모든 시드는 계속 평가한다.
모든 탐색이 끝나면 초기 관절 자세와 관절각 거리가 가장 가까운 안전 후보를
선택한다. 0번 시드는 초기 자세 자체에서 시작하고, 나머지는 Panda 관절
한계 안에서 균일하게 뽑는다.

기존 YAML의 `safe_ik.integration_period`와 `safe_ik.duration_per_seed`는
제거하고 `safe_ik.iteration_number: 1000`으로 바꾼다. 이전 항목이 남아 있으면
조용히 무시하지 않고 오류로 안내한다. 이전에 수치 간격을 0.01 이외의 값으로
사용했다면 반복 횟수만 환산해도 업데이트 크기까지 같아지는 것은 아니다.

### IK와 궤적 제어의 자기 충돌 모델 선택

IK 반복에 사용할 모델은 `safe_ik.self_collision_model`, 실제 궤적 제어에
사용할 모델은 `safety.self_collision_model`로 따로 선택한다. 예를 들어:

```yaml
safe_ik:
  self_collision_model: capsule  # IK 반복: 캡슐
  # 나머지 IK 설정은 유지
safety:
  self_collision_model: rdf      # 실제 제어: 학습한 RDF
  # 나머지 안전 설정은 유지
```

두 항목 모두 `rdf` 또는 `capsule`을 사용한다. IK 항목을 생략하거나 `null`로
두면 궤적 제어용 설정을 따르므로 기존 YAML의 동작은 그대로다.
`configs/panda.yaml`에서 두 항목을 각각 편집할 수 있다. 직렬 실행과 모든
병렬 worker는 같은 IK 모델을 사용한다.

이 선택은 **자기 충돌 모델**을 바꾼다. 장애물은 두 방식 모두 기존 캡슐–구
검사를 사용한다. 캡슐에는 `safety.margin`, RDF 자기 충돌에는
`safety.rdf.physical_margin + error_margin`이 적용된다. 기존 마진, 충돌 제외 쌍,
반복 수, 자세 허용오차, 연속 유지 조건은 자동 변경하지 않는다. 캡슐과 RDF는
형상과 여유가 다르므로 한쪽 통과가 다른 쪽 통과를 보장하지 않는다.

서로 다른 모델을 선택하면 모든 IK 후보를 **제어용 모델로 한 번씩 재검사**한다.
유한한 장벽값·기울기와 모든 장벽 `h >= 0`을 만족한 후보만 제어기에 넘기고,
그중 초기 자세에 가장 가까운 후보를 선택한다. 모두 탈락하면
`ik_candidates_unsafe_for_trajectory`로 종료하며 움직이지 않는다. 이 경우
자세 전용 진단 탐색으로 다시 시도하지 않는다. 후보의 `minimum_barrier`는
IK 모델 기준을 유지하며, 제어 모델의 후보별 장벽과 탈락 사유는
`summary.json`의 `safety.ik_candidate_validation`에 별도로 기록한다.
재검사는 후보 **끝점**에 대한 검사이지 연결 경로의 안전 보증은 아니며,
이동 중의 원래 CBF 제약과 RDF 초기 안전 검사는 그대로 적용한다.

두 모델이 같으면 평가기를 공유하고 별도의 후보 재검사를 추가하지 않는다.
한쪽이라도 RDF를 사용하는 순차 실행은 검증된 호환 RDF 산출물이 필요하며,
파일 누락·검증 실패를 캡슐로 자동 대체하지 않는다. 직접 제어 모드는 IK를
생략하므로 IK에만 지정된 RDF를 로드하거나 worker를 만들지 않는다.

시작 로그에는 IK와 제어 모델을 함께 표시한다. 결과의 `safety.model`은 제어
모델, `safety.safe_ik_model`은 IK 모델이며, 직접 모드에서는 후자가 `null`이다.
`safe_ik_rdf` 시간은 실제 IK 평가기/worker에서 집계하고, 제어용 RDF의 후보
재검사 시간은 `ik_candidate_validation.wall_time`으로 구분한다. 재검사 시간은
`safe_ik.wall_time`에도 포함한다. IK에서만 RDF를 사용해도 산출물 경로와 SHA를
실행 기록에 보존한다.

사용자 정의 `PandaRuntime`에서 서로 다른 모델을 주입할 때는 `ik_safety`를
명시해야 한다. `ik_search_factory`를 전달한다면 같은 IK 평가기를 사용하도록
구성한다. 기본 구성 함수는 이 연결과 worker 생성을 처리한다.

### 반복 내부의 평가 결과 재사용

한 IK 반복에서는 말단 자세·Jacobian과 `safety.evaluate(q)`를 각각 한 번만
호출한다. 반환된 `BarrierEvaluation`의 장벽값·관절 기울기를 후보 판정에
사용하고, 영공간 업데이트는 같은 객체의 `barriers.softmin(temperature)`로
계산한다. 이 메서드는 배열 집계만 수행하며 FK나 RDF를 다시 호출하지 않는다.
`safety.softmin(q, temperature)`는 외부 호출부를 위한 호환 래퍼로 유지한다.

softmin은 기존의 $-\tau\log\sum_i\exp(-h_i/\tau)$를 그대로 사용한다.
설정의 `softmin_temperature`는 $\tau$이며 역수 $\beta$로 바꾸지 않는다.
빈 장벽 집합은 값 $+\infty$와 영벡터 기울기를 반환한다. 평가 객체는 각 반복의
지역 변수이므로 다음 자세나 다른 worker에 잘못 재사용하는 전역 캐시는 없다.
자세 전용 진단에서도 기존 `minimum_barrier` 기록을 유지하기 위해 평가는
수행하지만, 안전 기울기를 관절 업데이트에 사용하지 않는 기존 동작은 유지한다.

RDF는 변경 전에도 동일 자세의 마지막 평가를 캐시했고, Pinocchio의 FK와
관절 Jacobian도 동일 자세에서 재사용했다. 따라서 이 리팩터링은 RDF 추론을
2회에서 1회로 줄인 변경이 **아니다**. 캐시 조회를 거치는 두 번째 평가 호출과
중복 말단 자세·Jacobian 조회를 없애며, 캡슐 평가기에는 실제 중복 계산 제거
효과가 있다. 모델, query point, top-k, float64, 마진, 충돌 제외 쌍, 수렴 조건과
궤적 제어의 CBF 제약은 변경하지 않는다.

2026-10-01 로컬 측정에서는 설치된 BP24 모델과 사용자 설정
(`top_k=40`, `physical_margin=0.010`)을 유지하고, 한 시드 40회 반복을
기존 호출 방식과 새 방식으로 각각 워밍업 후 5번씩 번갈아 실행했다.
BLAS/OpenMP 스레드는 1로 제한했고, 모델 로딩·GUI·궤적 제어는 측정에서 제외했다.

| 항목 | 기존 호출 방식 | 명시적 재사용 |
| --- | ---: | ---: |
| 안전성 평가 API 호출 / 40회 반복 | 80 | 40 |
| 말단 자세·Jacobian 조회 / 40회 반복 | 80 | 40 |
| 실행 시간 중앙값 | 4.136 s | 4.160 s |
| 실행 시간 범위 | 4.114–4.157 s | 4.051–4.315 s |

이 표는 안전성 **API 호출** 수이지 RDF 추론 횟수가 아니다. 기존 캐시가
작동하므로 이 측정에서 RDF 실행 시간 개선은 확인되지 않았으며, 중앙값은
오히려 약 0.6% 길고 측정 범위는 겹친다. 실제 RDF 가속에는 별도로 다항식·미분
평가 내부 비용을 줄여야 한다. 이 결과를 2배 가속으로 해석하지 않는다.

## 초기 시드 병렬 탐색

CLI는 `tqdm`으로 완료 시드 수와 실제 반복 수를 표시한다. 반복 수는 별도
콜백 이벤트로 전달하며 수치 업데이트·수렴 조건을 바꾸지 않는다. 병렬 실행은
먼저 완료된 작업부터 표시하되 결과는 기존처럼 시드 인덱스로 정렬한다.
`--visualize`/`make panda-view`는 전체 계산·worker 종료·결과 저장 후 기록만
재생한다. 진행률 단위와 재생 종료 동작은 [Make 안내](make_commands.md#panda-계산-진행-표시와-재생)를 참조한다.

```yaml
safe_ik:
  max_restarts: 10
  workers: 4  # 예시: 1은 직렬, 2 이상은 독립적으로 생성한 프로세스
```

`application/parallel_ik.py`가 프로세스 풀을 관리한다. 각 작업자는
자체 Pinocchio 모델·Data·캐시와 설정된 안전 평가기를 한 번 생성하고
배정된 시드에 재사용한다. IK가 RDF 모드이면 각 작업자가 산출물을 직접
로드하고 검증한다. 사용 중인 기구학 객체, MuJoCo 상태, 뷰어는 직렬화하지
않는다. `spawn` 시작 방식으로 주 프로세스의 네이티브·뷰어 스레드가
상속되는 것을 피한다. 최대 `min(workers, max_restarts)`개 프로세스를
사용하고 궤적 제어 전에 풀을 닫는다. 안전 IK 후보를 찾지 못하면 같은 풀로
자세만 검사하는 진단 탐색을 수행한다. 작업자 오류는 목표 자세 도달 불가로
오분류하지 않고 호출자에게 전달한다. 직접 제어 모드는 IK와 풀 생성을 모두
생략한다.

`domain/safe_pose_ik.py`의 `solve_seed()`가 수치 반복을 수행한다.
부모 프로세스는 기존 난수 순서로 모든 시작 자세를 생성한다.
0번은 요청한 초기 자세이고, 이후는 관절 한계 내 균일 표본이다.
가장 가까운 후보를 고르기 전에 시드 인덱스로 결과를 정렬하므로,
작업 배정 순서와 관계없이 직렬 실행의 동률 처리 규칙을 유지한다.
유지 시간과 시드별 반복 예산은 바뀌지 않으며, 한 시드 내부의 반복은 직렬이다.

기존 YAML에서 `workers`가 빠지면 기본값은 1이다. 현재 편집 가능한
`configs/panda.yaml`은 5를 명시한다. `workers`는 양의 정수여야 한다.
적용한 작업자 설정은 보관 YAML과 해석된 설정에 포함된다.
`safe_ik.wall_time`에는 안전 탐색 중 작업자 시작 시간이 포함되지만,
선택적인 자세 전용 진단 탐색과 풀 종료 시간은 포함되지 않는다.

사용 가능한 CPU 코어 수에 맞게 작업자 수를 선택한다. 짧은 탐색은 프로세스
시작 비용 때문에 더 느릴 수 있다. BLAS가 작업자마다 많은 네이티브 스레드를
생성하면, 명령 실행 전 `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`,
`OMP_NUM_THREADS`를 1로 제한해 스레드 과다 생성을 피할 수 있다.
실제 가속률은 장비와 작업량에 따라 달라진다. 수학적 동등성은 수치 허용오차로
검사하며, 장비나 BLAS 구현이 달라도 비트 단위로 같다고 보장하지 않는다.

병렬 탐색을 시작하는 Python 스크립트는 `if __name__ == "__main__":`
아래에서 호출해야 한다. 제공 CLI에는 이미 이 보호 구문이 있다.
사용자 정의 실행 환경은 `ik_search_factory`를 전달할 수 있다.
없으면 도메인 해법이 현재 프로세스에서 실행되어 메모리 내 테스트 구현도
계속 사용할 수 있다.

개발 장비의 2026-09-23 측정에서 시드 10개의 탐색은 직렬로 34.38초,
작업자 4개로 12.97초가 걸렸다(약 2.65배 가속).
이 측정에는 풀 생성·종료 시간이 포함됐다. 두 실행 모두 4번 시드를
찾고 선택했으며, 후보별 반복 횟수가 같고 관절값은 절대 허용오차 1e-11
이내로 일치했다. 이는 당시 조건의 단일 측정이며 보장된 가속률이 아니다.

## 충돌 모델

`PandaCapsuleSafety`는 구–캡슐 장애물 장벽과 비인접 캡슐 쌍을 평가한다.
직접 인접한 연결 부재와 설정된 고정 본체 제외 쌍은 생략한다.
캡슐 끝점은 저장소의 충돌 메시를 바탕으로 정한 프레임 로컬 좌표다.

현재 자기 충돌의 기본값은 `PandaRDFSafety`이며, 외부 장애물에는
기존 구–캡슐 계산을 유지한다. 제어기와 IK가 공통 장벽·기울기 인터페이스를
사용하므로 같은 RDF가 안전 목적, 후보 검증, 궤적 CBF에 연결된다.
기존 캡슐 자기 충돌은 명시적으로 선택할 수 있다.
현재 생성된 RDF 산출물은 거리 검증에 실패했으므로 실행 시 거부된다.
상세한 적용 범위는 [RDF 구현 상세](panda_rdf_implementation.md)를 참조한다.

## 궤적 제어기

순차 모드에서는 선택된 안전 IK 자세로 각 링크 끝점 목표를 정한다.
설정된 중간 프레임 $i$마다 다음을 사용한다.

$$
V_i(q)=\frac12\lVert p_i(q)-p_i(q^*)\rVert^2.
$$

각 끝점이 설정된 단계 허용오차 안에 들어오면 다음 프레임으로 진행한다.
마지막 단계는 요청한 말단 장치 위치·방향을 사용한다.

$$
V_{pose}(q)=\frac12\lVert p(q)-p_d\rVert^2
+\frac{w_O}{2}\lVert e_O(q)\rVert^2.
$$

방향 가중치 $w_O$는 YAML의 `trajectory.orientation_weight`다.
직접 제어 모드는 끝점별 중간 단계를 생략하고 처음부터 같은 자세 CLF를
사용한다. 목표 자세에서 CLF를 직접 정의하므로 안전 자세 IK 탐색과
후보 검증도 생략한다. 따라서 IK 후보 전환은 없다.
다만 RDF 산출물 검증과 궤적 초기 안전 검사까지 생략하는 것은 아니다.
Panda 궤적 제어는 관절 구성 공간 CLF를 사용하지 않는다.

쿼터니언 오차의 스칼라·벡터 쌍 $(\eta,e_O)$와 월드 좌표계 각속도
Jacobian $J_\omega$에 대해 최종 CLF 기울기는 다음과 같다.

$$
\nabla_q V_{pose}=(p-p_d)^T J_v
-\frac{w_O}{2}\eta e_O^T J_\omega.
$$

QP에는 다음 제약을 적용한다.

$$
\nabla V\dot q-\delta\le-cV,
\qquad
\nabla h_i\dot q\ge-\alpha h_i.
$$

CLF만 완화한다. CBF, 관절 위치, 속도, 명령 변화율(가속도)은 완화할 수 없다.
RDF 자기 충돌 행에는 `safety.rdf.cbf_gain`을 사용한다.
QP에 가능한 해가 없으면 속도 0을 반환하고 실행을 중단한다.
성공 전에 설정된 시간창의 관절 속도 2-노름 이동평균이 정지 임계값보다
작아지면 다음 안전 IK 후보를 사용한다.

## 실패 사유

- `pose_ik_unreachable`: 장애물 제약을 요구하지 않는 진단 탐색이 설정된
  다중 시작 예산 안에 목표 자세에 도달하지 못했다.
- `safe_pose_ik_not_found`: 자세 IK는 찾았지만 모든 안전 장벽을 통과하는
  후보가 없었다.
- `unsafe_initial_state`: RDF 모드에서 궤적 초기 상태의 장벽이 음수여서
  제어 시작을 거부했다.
- QP 실행 불가능: 안전 IK가 있어도 현재 상태에서 완화 불가능한 궤적
  제약을 만족할 수 없어 제어기를 중단했다.
