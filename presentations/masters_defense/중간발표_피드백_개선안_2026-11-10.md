# 석사 중간 발표 피드백에 따른 기존 발표자료 개선안

- 검토일: 2026-11-10
- 배경: 석사 중간 발표 심사 피드백. 다음 심사 발표가 예정된 상태.
- 검토 대상: 기존 `masters_defense` 발표자료, 한국어 대본 및 관련 실험 기록. 별도로 만든 CICS 발표자료는 대상이 아님.
- 페이지 기준: 검토 시점의 본문 36장·부록 21쪽인 발표자료.
- 상태: **개선 제안 기록. 발표 슬라이드와 대본에는 미적용.**

## 핵심 진단

가장 중요한 개선점은 **“남아 있는 문제 → 설계 선택 → 효과의 근거 → 남은 한계”를 명확히 연결하는 것**이다. 현재 자료에도 필요한 내용이 상당 부분 들어 있지만, 핵심 설명이 대본이나 후반부에 있어 청중이 연구의 의미를 스스로 연결해야 하는 구간이 있다.

특히 Direct만 성공한 사례와 방법의 한계는 이미 자료에 포함되어 있다. 정보를 단순히 추가하기보다, 각 결과가 어떤 설계 문제와 후속 시도로 이어지는지를 명확히 해야 한다.

## 1. 7쪽: 연구 질문에 앞서 해결하려는 문제와 기존 연구와의 차이 구체화

현재는 Reis·Tan·Gonçalves의 접근을 설명한 뒤 “로봇팔의 운동학적 구조를 어떻게 활용할 것인가?”라는 질문으로 끝난다. 여기서 다음 연결이 필요하다.

> 안전한 목표 IK가 존재하더라도, 최종 end-effector task를 바로 추종하는 제어가 그 목표에 도달하는 것은 아님. 본 연구는 IK에서 link별 목표를 구성하고, 실행할 subtask를 선택하는 방식으로 이 문제에 접근.

비교 기준도 **“무엇을 바꾸어 목표 진행을 유도하는가?”**로 통일하면 좋다. 현재 소개한 연구의 CLF 형상·nominal input·circulation과, 본 연구의 **IK 기반 subtask 구성 및 선택**을 대비하는 것이다.

다만 이것만으로 문헌 전체의 research gap이 확립되지는 않는다. CLF–CBF 연구와 학습 기반 연구에 더해, **IK 기반 subgoal·계층적 제어·task sequencing 연구**를 확인해야 “IK를 사용한다”보다 구체적인 차별점을 주장할 수 있다.

“기존 방법은 로봇팔의 특성을 활용하지 않는다”는 표현은 피하는 편이 타당하다. 기존 방법에서 사용하는 로봇 형상·관절 정보와, 본 연구에서 IK로 link-level subtask를 구성하는 절차를 구분해야 한다.

## 2. 학습 기반 방법과의 비교: 학습이 무엇을 결정하는지 먼저 제시

현재 학습과 QP의 역할 분담은 30쪽에서 명확해진다. 이를 초반 문헌조사에서도 짧게 예고하면 강화학습 관련 질문에 답하기 쉬워진다.

권장 설명:

> 학습기는 실행 전에 사용할 link subtask를 선택하고, 실제 joint velocity는 매 제어 주기 CLF–CBF QP가 결정. 실행 중 선택된 subtask, 활성 CLF, 안전 제약을 추적할 수 있는 구조.

이는 “제어 동작을 설명할 수 있다”는 답변을 구체화한다. 다만 **신경망이 왜 그 pair를 선택했는지까지 설명한 것은 아니다.**

RL에도 CBF를 결합한 연구가 있으므로 “RL은 안전성을 다루지 못하지만 우리 방법은 가능하다”는 비교는 성립하지 않는다. 비교할 대표 방법을 정하고 다음 기준을 비교해야 한다.

- 학습 출력
- 안전 제약 처리
- 필요한 모델과 입력 정보
- 실험 조건

현재 발표 결과로 RL 대비 성능 우월성을 주장할 수는 없다. 구조적 차이와 실험적으로 입증한 성능 차이를 구분해야 한다.

참고: [Cheng et al., End-to-End Safe Reinforcement Learning through Barrier Functions for Safety-Critical Continuous Control Tasks](https://arxiv.org/abs/1903.08792).

## 3. 9·12·19쪽: “왜 잘 되는가”를 방법 설명 전에 제시하고 결과에서 확인

9쪽의 사람 행동 연구는 발상의 출처를 보여준다. 제어기의 작동 원리는 다음 연결로 따로 설명하는 것이 좋다.

> 활성 subtask 변경 → QP에 요구하는 오차 감소 방향 변경 → 팔의 configuration 변화 → 다른 상태에서 최종 end-effector regulation 수행

이 설명을 12쪽 전에 제시하면, 청중이 단계별 그림을 보면서 각 단계의 목적을 이해할 수 있다. Direct에도 CLF slack이 있으므로 **“Direct는 EE 오차 증가를 허용하지 않는다”**고 설명해서는 안 된다.

19쪽의 **“Resolving Deadlock”**도 주장 범위를 점검할 필요가 있다. 사용한 episode 30의 Direct 실패 분류는 QP infeasibility이다. 또한 별도의 Panda 정체 진단에서는 정체한 네 사례 모두 EE CLF 감소 방향이 존재했다.

따라서 모든 정체를 local minimum으로 설명하기보다, **일부 상태에서 task 변경이 더 유리한 진행 방향을 제공한다**는 수준으로 설명하는 편이 근거에 맞다. 해당 Panda 진단은 현재 본문 주실험과 구분되는 별도 조건의 분석이므로 통계와 실험 조건을 혼합하지 않아야 한다.

이론 분석을 추가한다면 **볼록 QP 자체의 국소 최솟값과, QP 제어기로 구성한 폐루프의 비목표 평형점**을 먼저 구분해야 한다. 동일한 상태에서 Direct와 각 subtask의 최적 입력·활성 제약을 비교하는 분석부터 시작할 수 있다.

근거: [Panda 정체 진단 기록](/home/jinoo/prj/safe-inv-clbf-robot-arm/docs/experiments/panda_all_links.md:790).

## 4. Direct를 일반 구조의 특수한 경우로 설명

18쪽에는 이미 Direct만 성공한 **10개 episode**가 표시되어 있다. 이 결과를 본 연구의 설계 문제로 연결하면 좋다.

> Link subtask가 도움이 되는 episode도 있고, 처음부터 end-effector를 제어하는 편이 나은 episode도 존재. 따라서 어떤 subtask를 얼마나 사용할지가 선택 문제.

중간 link subtask 수를 \(L\)이라 하면, **\(L=0\)은 Direct**로 설명할 수 있다.

다만 현재 학습기는 **오름차순으로 실행하는 10개 two-link pair**만 선택한다. Direct 선택이나 자유로운 순서 선택까지 학습한 것은 아니다. 일반적인 제어 구조와 현재 구현·평가 범위를 구분해야 한다.

Direct를 후보에 추가해도 선택 오류가 가능하므로 성능 향상은 별도 검증 대상이다. Direct를 포함하는 후보 집합으로 확장하는 것과, 그 선택 정책의 성능을 입증하는 것은 별개의 작업이다.

## 5. 실험 조건 관련 질의응답 정리

| 심사 질문 | 현재 자료에 맞는 설명 | 개선 위치 |
|---|---|---|
| 장애물 위치를 알면 쉬운 문제 아닌가? | 장애물 인식은 주어진 것으로 가정. 위치와 안전한 목표 IK를 알아도, whole-arm 제약 아래 목표에 도달하는 제어는 별도 문제 | 3쪽 문제 정의 |
| 시작 자세가 모두 \(q=0\)인가? | **Planar 300개는 고정 \(q_0=0\)**. **Panda는 안전한 무작위 초기 자세** | 18·24쪽 실험 조건 |
| IK를 바꾸면 실패가 줄어드는가? | 현재 발표의 Panda 비교는 episode마다 하나의 IK를 고정. IK 재선택의 효과는 현재 결과로 입증되지 않음 | 실패 분석·향후 계획 |
| Sequential 실패는 순서를 바꾸면 해결되는가? | 가능한 개선 방향. 실패 원인과 순서 변경 효과의 검증 필요 | Direct-only 사례 설명 |
| 느린 장애물 이동이나 위치 갱신에도 동작하는가? | 관련 평가 기록을 확인하지 못함. 메모가 이동 속도인지, 측정·갱신 지연인지 먼저 확인 필요 | 확인 후 실험 계획 |

특히 장애물 위치에 관한 질문에 “구로 표현하는 장점”을 답하면 질문의 핵심에서 벗어난다. **알고 있는 환경에서도 무엇이 어려운지**를 답해야 한다.

“\(q=0\) 이외의 경우도 실험했다”는 답변은 모델을 구분해야 한다. 현재 본문의 Planar 결과를 임의의 초기 자세에서 검증한 결과처럼 소개하면 안 된다.

근거: [Panda 초기 상태·고정 IK 프로토콜](/home/jinoo/prj/safe-inv-clbf-robot-arm/docs/experiments/panda_link_dataset.md:30).

## 6. 파트 마지막에 효과와 한계를 한 쌍으로 제시

모든 슬라이드에 takeaway를 넣을 필요는 없다. 다음 세 지점에서 청중이 판단을 내릴 수 있도록 하면 된다.

| 파트 | 확인한 효과 | 함께 말할 한계 |
|---|---|---|
| Planar, 18–19쪽 | 전체 성공 수 증가 | Direct만 성공한 episode도 존재 |
| Spatial·단계 축소, 24–26쪽 | Subtask 감소로 공동 성공 episode의 완료 시간 감소 | 후보 평균 성공률도 감소 |
| Learning, 31–34쪽 | 후보 평균 대비 성공률 향상 | 최고 단일 pair 대비 우월성은 미확립, oracle과 차이 존재 |

이렇게 마무리하면 다음 파트의 필요성도 자연스럽게 연결된다.

> 단계를 줄이면 빨라지지만 성공률이 낮아짐 → episode별 선택이 필요함

이 연결이 학습 도입의 이유가 된다. “무엇이 효과가 있었고, 어떤 문제가 남았는가”를 각 파트의 마지막에 명시하는 것이 심사 피드백에 대한 직접적인 보완이다.

## 7. 20–23쪽: 구현상의 어려움과 기존 기술의 역할 연결

현재는 RDF, null-space IK, quaternion 수식이 순서대로 등장한다. 각 설명을 다음 난점에서 시작하면 실제 구현 기여가 더 잘 드러난다.

| 구현상의 난점 | 연결할 처리 방법 |
|---|---|
| 목표 pose를 만족하는 IK 중 안전한 후보를 찾는 문제 | Clearance를 고려한 탐색과 후보 검증 |
| 복잡한 link 사이의 거리와 변화율을 계산하는 문제 | RDF query와 양쪽 link의 운동을 반영한 gradient |
| Subtask를 많이 거치면 시간이 늘어나는 문제 | 단계 축소와 episode별 선택 |

RDF나 null-space IK 자체의 발명과, 이를 Sequential 제어에 연결해 구현·검증한 작업은 구분해서 설명해야 한다.

## 8. 시간 배분과 발표 연습을 핵심 기여 중심으로 조정

현재 대본의 시간 배분은 다음과 같다.

| 설명 구간 | 배정 시간 |
|---|---:|
| 1–10쪽 | 5분 |
| 12쪽: IK → link target → subtask 구성 | 10초 |
| RDF와 IK 계산 설명 합계 | 115초 |

핵심 아이디어를 이해하는 데 필요한 시간이 부족하다. 12쪽 설명을 충분히 늘리고, 상세 loss나 IK 계산식의 발화량을 조정하는 것을 권한다.

약어도 사전 슬라이드를 추가하기보다 첫 등장 위치에서 풀어 쓰면 된다. 특히 **QP, IK, DOF**가 우선 점검 대상이다. ST는 link-level subtask의 의미를 먼저 설명한 뒤 기호를 도입하는 편이 좋다.

연습은 우선 다음 세 설명을 슬라이드 없이 연결해서 말하는 방식이 좋다.

- **1분:** 어떤 문제가 남아 있고, 왜 이 접근을 선택했는가.
- **2분:** IK에서 subtask를 만들면 동작이 어떻게 달라지는가.
- **1분:** 무엇이 개선되었고, 무엇은 아직 확인하지 못했는가.

다음 심사가 남아 있는 만큼 35쪽도 **“남은 질문 → 확인할 실험 → 판단 기준”**으로 구체화하면 좋다.

## 추가 확인이 필요한 피드백

- **“장애물의 위치가 느리게…”**: 장애물의 이동 속도를 뜻하는지, 측정·위치 갱신 지연을 뜻하는지 확인 필요. 의미를 확정하기 전에 동적 장애물이나 지연에 대한 성능으로 해석하지 않음.
- **“모의실험 시연 결과”**: 제목만 기록되어 있어 교수님의 구체적인 의견 확인 필요.

위 항목의 의미를 확인한 뒤 다음 발표의 실험 계획과 시연 구성에 반영할 것.
